# 基建-订单库实现说明

## 当前行为

任务先接续到自己的订单库，按固定 4×2 共 8 个栏位进行扫描。好友等级不足导致栏位少于 8 个时，只处理实际识别出的订单，不视为错误。

支持的订单条件如下：

- 构建票订单：默认选择消耗 6、8、16 的订单，可在 MFA 中改选 10、18。
- 稀有星币订单、稀有技术点订单：分别由复选框控制。
- 自动合成：每类订单独立控制，只合成当前订单相对库存缺少的数量。
- 好友订单：同一种订单以“类型、普通/稀有、消耗数量”组成当日签名；成功交付后，当天其他好友不再重复检查该签名，不影响自己的订单库。

自己的订单库处理完成后进入好友列表，从第一位好友开始逐个扫描。切换再次回到自己的订单库时视为好友遍历完成，随后返回主界面结束任务。

## 识别方式

`agent/base_order_pipeline.py` 对每个固定栏位分别执行 OCR：

- 根据“构建订单、星币订单、技术点订单”判断类型。
- 从消耗区域读取 1 至 99 的数量。
- “稀有”优先使用文字，红色标签比例作为补充。
- “可交付”优先使用文字，黄色按钮比例作为补充。
- “资源暂缺/素材不足”用于决定是否进入自动合成。

Pipeline 使用 1280×720 坐标基准。Agent 使用 1920×1080 录制基准，但所有点击和 ROI 都通过 `viewport.py` 按当前截图尺寸换算，因此不依赖单一分辨率。

## 架构边界

- `assets/resource/pipeline/base/基建-订单库.json`：正式页面流、分支、循环、返回和结束条件，包含 `$__mpe_code`。
- `agent/base_order_domain.py`：不依赖 MaaFramework 的纯规则，可离线测试。
- `agent/base_order_pipeline.py`：Pipeline 调用的原子识别和动作，不包含完整跨页面工作流。
- `tools/test_base_order_logic.py`：订单规则离线测试。
- `tools/test_pipeline_refactor.py`：Pipeline/MPE/Agent 分层守卫。

## 当前进度

旧 LAA 已完成主要业务逻辑，但属于单体 Agent 实现且坐标固定。当前项目已按现行架构迁移业务规则、正式 Pipeline、MPE 信息、MFA 设置和多分辨率换算。离线规则与结构测试可覆盖筛选、好友去重、流程节点和架构边界；真实订单交付与素材合成会消耗游戏资源，尚需在用户明确允许后进行实机验收。
